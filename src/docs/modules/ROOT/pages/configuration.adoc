= Configuration
:description: Settings in application.properties, and how paths are resolved.

Settings live in `web/src/main/resources/application.properties`. Every one can be overridden on
the command line with `-D`, or by an environment variable.

== electroMe settings

[cols="2,1,3"]
|===
| Property | Default | Meaning

| `electrome.usage.csv`
| `../MyUsageData_19-08-2026.csv`
| Your interval data file. See <<paths>>.

| `electrome.plans.dir`
| `../plans`
| Directory of plan YAML files. Every `.yaml` or `.yml` in it is loaded.

| `electrome.shortlist.name`
| `.shortlist`
| File holding the plans you have picked from the market, written in the plans directory.

| `electrome.baseline.plan`
| `agl-flat-current`
| The `id` of the plan you are actually on. Savings are measured against it.

| `electrome.default-window-days`
| `365`
| How far back the date range reaches when the page first opens. Clamped to the data you actually
have.

| `electrome.market.enabled`
| `true`
| Whether the xref:market-plans.adoc[market harvest] is offered. Set `false` to hide it entirely.

| `electrome.market.zone`
| `AUSNET`
| Which distribution network to harvest plans for.

| `electrome.market.cache-dir`
| `../.cdr-cache`
| Where harvested plan responses are cached. Gitignored.
|===

== Quarkus settings

[cols="2,1,3"]
|===
| Property | Default | Meaning

| `quarkus.http.port` | `8080` | Port the application listens on.
| `quarkus.qute.property-not-found-strategy` | `throw-exception` | Deliberate: a typo in a template
should fail loudly during development rather than render an empty string.
|===

== Overriding at run time

[source,bash]
----
gradle21w quarkusDev -Dquarkus.args="" \
  -Delectrome.usage.csv=/Users/me/Downloads/usage.csv
----

Or by environment variable, uppercased with dots as underscores:

[source,bash]
----
ELECTROME_USAGE_CSV=/Users/me/Downloads/usage.csv gradle21w quarkusDev
----

[#paths]
== How relative paths are resolved

A relative path is tried against the working directory, then against each parent directory in
turn, until the file is found.

This is not a convenience. The working directory is not stable across the ways the application
runs: tests start in the module directory, development mode starts in `build/classes/java/main`,
and a packaged build starts wherever you launched it. A plain relative path would resolve
differently each time and present as "no data found" rather than as a path problem.

Absolute paths are used exactly as given.

== Startup behaviour when files are missing

Neither the usage file nor the plans directory is required for the application to start. A missing
or unreadable file is reported on the page, naming the absolute path it looked for, rather than
failing the boot. Someone who has not yet exported their data should get an explanation, not a
stack trace.

[#baseline]
== Why the baseline plan is set, not inferred

`electrome.baseline.plan` is a plain property because there is no rule that can work it out.
Nothing about a directory of plan YAML files says which one a given household actually signed up
to and is paying under — two plans can differ only in a rate that never shows up in the usage
data, and the plan you are on is not necessarily the cheapest, the newest, or in any way
distinguishable from the others by inspection. Only the household knows, so the household says.

When the property is set and its `id` matches a loaded plan, the dashboard's shortlist gains a
"vs your plan" column, showing what switching to each other plan would have saved over the window,
and the row for the baseline plan itself reads "your plan" rather than a saving figure.

When it is left blank, or names a plan that is not among the ones loaded, nothing breaks. The
comparison still ranks every plan against every other; it just does so with no "vs your plan"
column, because there is nothing to compare against. That degrading gracefully is deliberate: a
missing or non-matching baseline plan id is a configuration gap, not an error, and it must never
be the reason the page fails to render.
